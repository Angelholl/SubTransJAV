## 一、测试/正式双库约定（强制）

所有测试-修复-测试循环（调参、改规则、验证行为）**必须**加 `--tm-db` 用独立测试库，只有正式出片跑才允许用主库。原因：TM 学习会把测试跑的中间态/错误译文固化进库并跨片扩散（2026-09 审计实证：机械缺陷 80 条、行错位簇 14 条、系统性误译ザコ→小穴 5 条均已清洗，记录见 `.analysis_tmp/tm_clean_20260908.md`）。

```bat
:: 测试跑标准模板（--tm-db 指向测试库）：
.venv\Scripts\subtransjav-refine --input-dir "<输入目录>" -r --filter-pattern "*.merged.subtransjav.srt" --exclude "*_final_cn.srt" "*_refine_*" --pipeline v2 --profile local --s1-provider lmstudio --s1-model <模型名> --s3-provider lmstudio --s3-model <模型名> --lmstudio-endpoint http://localhost:1234/v1 --v2-concurrency 1 --tm-db "./Temp/translation_memory/tm_test.db"

:: 正式跑：不加 --tm-db（默认主库）；单文件重跑加 --force
```

- 测试库污染直接删除重建（从主库复制或空库均可）。
- `--tm-clear`+`--tm-import` 回灌会把全库 hit_count 归零，丢失高命中追踪信号；精确清洗走 SQL 按备份操作。
- 回灌定版口径（2026-09-09）：正式产物批次跑完后，以测试库为准全量覆盖主库——命中漂移（测试库 fork 后服务正式跑动的真实使用）与 upsert 新译文（经门槛+审校）均采纳；created_at、hit_count 全字段原样保留不重置。

## 三、周期审计复跑流程（每 5-8 部新片后执行）

1. **分层抽样评审**：高命中层（hit≥5）全审、中/零命中层各抽 70 条（判据 A严重错译 / B轻微瑕疵 / C1可接受 / C2翻译腔 / C3语气偏差；决策错误率只看 A+B；C2 不计入错误率只做分布统计）。
2. **机械缺陷全量清点**：Translation 泄漏 / 假名残留 / 源文前缀残留 / 占位符，带 hit_count 去重清单（口径见 `.analysis_tmp/run_clean_tm.py`）。
3. **ASR 噪声跨片复现快查**（纯只读 SQL）：扫「源文含 ASR 噪声特征（低频假名串/非词典形态）且 hit_count ≥10」的条目，按 created_at 批次判跨片（同批次=同片）。C2 进入高命中层单独标注。
4. **ASR 噪声固化干预**（2026-09-09 定版）：
   - **触发条件**：同一噪声源文跨 ≥2 部复现（不同 created_at 批次）**且** hit_count ≥10 才干预。单看 hit_count 会被正常高命中（`うん。→嗯。`）干扰。
   - **干预动作**：必须「删除该 TM 条目 + 加词库条目」二件套——光加词库拦不住已固化条目的命中替代（命中即跳过引擎，词库只影响未命中行）。
   - 词库兜底等足够样本量确认复现频率后再加，避免过度添加。
