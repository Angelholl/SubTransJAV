# SubTransJAV 使用与维护手册

面向中文用户的日文影片字幕双引擎翻译与精修工具链（v1.1）。本手册覆盖安装、配置、断点恢复、事件协议、翻译记忆库（TM）运维与常见问题，供日常使用与长期维护参考。

> 面向中文用户：默认翻译方向为 日文 → 中文。精修管线（refine）与角色卡模板当前未做英文等其他目标语言适配。

---

## 1. 安装

### 1.1 桌面 GUI（推荐普通用户）

使用仓库根目录的 `首次安装.bat`：

1. 双击运行，脚本自动在项目目录创建 `.venv` 虚拟环境；
2. 自动安装核心引擎与 GUI 依赖（`pip install -e ".[gui]"`）；
3. 默认源失败或超时时自动回退清华大学镜像源重试；
4. 完成后使用桌面"净语翻译"快捷方式启动（或命令行运行 `subtransjav-gui`）。

前置要求：Windows 10+，已安装 Python 3.10+ 并加入 PATH；运行 GUI 还需 Microsoft Edge WebView2 运行时（Win10/11 通常已内置，缺失时见 FAQ-6）。

### 1.2 命令行 CLI（推荐进阶用户）

要求 Python 3.10–3.13。

```bat
:: 核心翻译引擎 + CLI
pip install -e .

:: 含桌面 GUI
pip install -e ".[gui]"
```

入口命令：

- `subtransjav-refine`：精修翻译管线（阶段A 净语+翻译 → 阶段B 审校+抛光）；
- `subtransjav-gui`：桌面界面。

## 2. 配置分层与可调字段

### 2.1 优先级（从低到高）

```
内置默认值 < config/user_settings.json < SUBTRANSJAV_* 环境变量 < CLI/GUI 显式赋值
```

- `config/user_settings.json`：浅合并，仅下方表格中的字段生效；非法 JSON 或未知字段会被警告并忽略，不会中断运行；
- 环境变量命名规则：`SUBTRANSJAV_` + 大写字段名，如 `SUBTRANSJAV_TIMEOUT_LLM=600`；
- CLI/GUI 显式赋值优先级最高（构造后赋值天然生效）。

### 2.2 全部可调字段与默认值

| 字段名 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `temperature_cloud` | float | `0.5` | 云端服务商采样温度 |
| `temperature_local` | float | `0.1` | 本地服务商采样温度（实测最优低温） |
| `premerge_max_gap_s` | float | `8.0` | 断句预合并：gap 阈值占位（跨度上限职责已移交 `premerge_max_span_ms`） |
| `premerge_max_items` | int | `3` | 断句预合并：合并条数上限 |
| `premerge_max_span_ms` | int | `5000` | 断句预合并：合并后总时长硬上限（毫秒） |
| `premerge_max_chars` | int | `80` | 断句预合并：合并后文本字符上限 |
| `premerge_min_fragment_chars` | int | `6` | 断句预合并：语义断裂档下一行短碎片阈值（字符） |
| `v2_concurrency_max` | int | `5` | 批间并发钳制上限 |
| `timeout_llm` | float | `900.0` | LLM 单批超时（秒；本地慢模型单批可达数分钟） |
| `timeout_http` | float | `60.0` | OpenAI 兼容 HTTP 客户端超时（秒） |
| `timeout_probe` | float | `5.0` | 本地服务探测类 GET 超时（秒） |
| `heartbeat_stale_s` | float | `45.0` | GUI 心跳超时阈值（秒；可经 `SUBTRANSJAV_HEARTBEAT_STALE_S` / `user_settings.json` 覆盖） |
| `dropped_log_rotate_mb` | int | `5` | `Errors/dropped_entries.log` 轮转阈值（MB），超限轮转为 `dropped_entries-<n>.log` |
| `v2_source_filter_valve_pct` | int | `50` | 闸门0 保险阀：单文件拦截率超过该百分比时降级为只计数（1-100） |
| `v2_asr_meta_min_coverage_pct` | int | `30` | 上游语音覆盖率低于该百分比时写入风险清单告警 |
| `v2_asr_meta_stale_max_hours` | int | `24` | 自动发现的上游 manifest 比 SRT 旧超过该小时数视为陈旧（放弃该信号） |
| `context_sidecar` | bool | `true` | v1.2.2：per-片语境 sidecar（`{字幕名}.context.md`，与输入 srt 同目录同名）注入开关——剧情摘要与误听怀疑表注入 A/B 提示词；`false`（或字符串 `"false"`）禁用。模板见 `docs/上下文sidecar模板.md` |

`config/user_settings.json` 示例：

```json
{"temperature_cloud": 0.3, "timeout_llm": 600}
```

LLM 服务商与端点（`--s1-*` 阶段A / `--s3-*` 阶段B，均为"净语翻译 v2"两阶段语义）不在上表内，经 CLI 参数或 GUI 设置；本地服务 LM Studio / Ollama 有内置默认端点（`http://localhost:1234/v1`、`http://localhost:11434/v1`），不需要任何密钥。

### 2.3 引擎自动化边界与缺省口径

refine 阶段的引擎自动拉起、换载、上下文窗口（ctx）与并发对齐仅覆盖 LM Studio 后端（`provider=lmstudio`）；Ollama 与自定义服务商无此能力，使用前需手动载入模型。

管线配置是引擎参数的唯一事实来源：任务启动后会自动按管线值对齐 ctx（缺省 22272）与并发（缺省 2），LM Studio 侧的手工修改会被覆盖回管线值。缺省 22272 / 并发 2 为作者 16GB 单卡（RTX 5060 Ti 16GB）实测档案值，其他显存容量请按自身硬件下调（可用 `--v2-ctx` 显式覆盖）。

## 3. 断点恢复（--resume / --force-resume）

### 3.1 工作机制

每次任务会持久化一份任务清单 `{字幕名}_manifest.json`，记录：

- 输入文件指纹（sha1、大小）、配置指纹、词库与 TM 指纹、各阶段模型信息；
- 各阶段状态机（`pending → running → done / degraded / failed`）与产物路径。

`--resume` 断点续跑：

1. 重算输入/配置/词库/TM 指纹并与清单比对；
2. 指纹全部匹配（清单可信）且阶段A 已完成、终稿未完成 → 复用上次中断任务的阶段A 产物（`{字幕名}_refine_A.srt`），直接进入阶段B；
3. 任一指纹不匹配 → 视为不可复用，整个任务从头重跑（清单按新指纹重建）。

`--force-resume`：配合 `--resume` 使用，指纹校验不匹配时仍强制复用旧产物（例如明知只改了无关配置、想省掉阶段A 费用时）。**注意：复用的阶段A 产物与当前输入可能不对应，需自行承担错位风险。**

### 3.2 与 --force 的区别

- `--resume`：复用**已完成的阶段A**，跳过重复计算；
- `--force`：忽略已有产物强制整任务重跑（覆盖前自动备份）。

### 3.3 manifest 自动清理

任务成功完成后，断点恢复相关产物（`{字幕名}_manifest.json` 与 `{字幕名}_refine_A.srt`）会被自动删除，不留垃圾文件；仅在任务中断/失败时保留，供下次 `--resume` 使用。

## 4. NDJSON 事件协议与退出码

### 4.1 开启方式

```bat
subtransjav-refine -i 字幕.srt ... --event-format ndjson
```

- 结构化事件以"每行一个 JSON 对象"输出到 stdout；人类可读文本全部转往 stderr；
- 心跳默认 20 秒一跳，可用 `--heartbeat-interval` 调整（GUI 依赖心跳判断进程存活）；
- 序列化使用 `ensure_ascii=True`，防止 Windows GBK 控制台破坏 JSON 行结构；
- 解析失败的行按普通日志处理（向前兼容）。

### 4.2 事件类型表（protocol_version = 1）

| 事件类型 | 含义 |
|---|---|
| `task_started` | 任务开始 |
| `phase_started` | 某阶段开始 |
| `phase_progress` | 阶段内进度推进 |
| `phase_finished` | 某阶段结束 |
| `warning` | 警告（不影响继续） |
| `degraded` | 静默降级显式化（该批/条目降级处理，如保留原文） |
| `error` | 错误 |
| `heartbeat` | 心跳（含 `last_phase` / `elapsed_s` / `interval_s`） |
| `task_finished` | 任务结束 |
| `gate0_summary` | 每文件闸门0 执行摘要（payload 含删除/检出计数、类别、保险阀、上游信号、隔离区候选，见 7.2） |

事件行公共字段：`protocol_version`、`task_id`、`seq`（单调递增）、`timestamp`（秒级 ISO）、`type`、`phase`、`file`、`payload`（对象）。

### 4.3 CLI 退出码

| 退出码 | 含义 |
|---|---|
| `0` | 成功（含 dry-run 计划校验通过） |
| `1` | 执行异常失败 |
| `2` | dry-run 配置错误 / 参数问题 |
| `3` | 部分降级（存在降级/失败文件或风险事件，产物已生成但需人工复核） |
| `130` | 用户中断（Ctrl+C） |

> 注：`2` = 用法/参数错误（argparse 惯例，非法参数时由 `SystemExit(2)` 产生），与任务退出码 `0`/`1`/`3` 并存。

## 5. 翻译记忆库（TM）运维

### 5.1 存储位置

- 主库默认路径：`<项目根>/Temp/translation_memory/tm.db`（SQLite，句子级翻译记忆）；
- 可用 `--tm-db` 指定其他库文件（例如为测试单独建库）；
- 与词库（术语级，CSV）互补：TM 是句子级，词库是术语级。

### 5.2 匹配与学习

- 匹配策略：精确匹配（哈希查找，直接复用译文）→ 模糊匹配（字符重叠率 ≥ 阈值，默认 `--tm-threshold 0.85`，候选供提示）；
- 自学习带**准入门槛**：低质/可疑翻译不进词库（`--no-tm-learn-gate` 可关闭，仅用于 A/B 验证）；
- `--tm-stats` / `--tm-export` / `--tm-import` / `--tm-clear`：统计 / 导出 CSV / 从 CSV 导入 / 清空。

### 5.3 回灌口径

主库与测试库分离维护；批量回灌（把外部或历史译文并回主库）统一走 `--tm-export` 导出复核后经 `--tm-import` 人工执行，不做自动回灌。导入前建议先备份 `tm.db` 并用 `--tm-stats` 核对条目量。

## 6. 风险清单文件

- 有风险时自动生成 `{字幕名}_风险清单.md` 与 `.json`（无风险不生成）；
- 内容为管线运行中收集的风险事件，严重级别分 `info` / `warning` / `critical`；
- 用途：定位需人工复核的片段（如未翻译占比过高、语义可疑、触发加固规则的行）；
- 退出码 `3`（部分降级）通常伴随风险清单，建议优先复核 `critical` 条目。

## 7. 双幻觉防护（闸门0 / 处置台账 / 隔离区）

"双幻觉"指两处幻觉：**第一重**为上游 ASR 转写幻觉（非语音被转写成文字：噪音、乱码、无意义音节、重复循环、片尾"感谢观看"式元信息）；**第二重**为 LLM 翻译幻觉（错译、编造，最隐蔽的是把乱码"翻译"成通顺中文）。1.2 起内置三道闸门：

### 7.1 闸门0：送翻前源侧检测（默认开启）

- 开关：`--source-filter strict|default|off`（默认 `default`）。**任何档位都不删除白名单词**；`off` 可完整回退 1.1 行为。
- 检测类别与档位行为：

| 类别 | default | strict | off |
|---|---|---|---|
| 纯标点行 / `!`串 / 不可发音辅音串 | 删除+归档 | 删除+归档 | 不处理 |
| 重复循环（相邻同文 ≥4 连） | 删除+归档 | 删除+归档 | 不处理 |
| 片尾元信息（时间轴末段+词表双闸） | 删除+归档 | 删除+归档 | 不处理 |
| 孤立应答词（はい/うん 等单独成行） | 只计数 | 删除（叠加位置+密度启发式） | 不处理 |
| 无意义音节连缀 | 只计数 | 删除（叠加启发式） | 不处理 |

- 用户白名单 `config/rules/source_hallucination.yaml` 的 `keep_list` 优先级最高（存在即整文件替换包内默认库，与 `translation_rules.yaml` 同惯例）。
- **保险阀**：单文件拦截率超过 `v2_source_filter_valve_pct`（默认 50%）时全文件降级为只计数（不删除），控制台显著警告 + 报告红标 + 风险清单 warning。
- 与上游关系：上游 v1.9.2 的 qwen 模式已在源头清理部分形态，但 **whisper 系模式与旧版上游不清理**——闸门0 对所有来源的 SRT 同样生效；增量价值在上游不处理的类别（不可发音串、重复循环、片尾元信息、无意义音节连缀）。

### 7.2 处置台账：质量报告【处置】章节与 gate0_summary 事件（1.2.1 起）

- **`{字幕名}_幻觉处置报告.json` 已退场**：早期 1.2 开发版曾随每个文件生成该 json（仅覆盖闸门0），1.2.1 起不再生成；旧版运行留下的残留文件会在成功运行后随恢复类清理自动删除，无需手工处理。其信息由质量报告承接：
  - **【处置】章节**：闸门0 送翻前删除台账——删除总数、按类别计数、删除样本（前 20 条），全量明细归档 `Errors/dropped_entries.log`；
  - **条数核对恒等式**：原文条数 = 闸门0删除 + 预合并合并 + 规则清洗合并/删除 + 隔离区移出 + 终稿，失衡时以 ⚠️ 标示两侧数值；
  - **【乱码强译复核】小节**：源文疑似转写乱码 × 译文通顺中文的条目逐条列出，提示人工复核语义是否被反转（拒绝↔邀请、停止↔继续等），不自动改稿。
- **机器可读通道**：NDJSON `gate0_summary` 事件（每文件闸门0 执行后发一次，payload 含计数/类别/保险阀/上游信号/隔离区候选摘要，见第 4 节事件表）。
- 运行末尾摘要仍显式输出每文件闸门0 计数行；删除条目同步归档到 `Errors/dropped_entries.log`（超过 `dropped_log_rotate_mb` 自动轮转）。

### 7.3 上游信号接入（--asr-meta，可选）

- `--asr-meta <whisperjav_run.json 或其目录>`：读取上游 WhisperJAV v1.9.2 运行清单；未提供时自动发现 SRT 同目录同名文件（新鲜度校验：manifest 比 SRT 旧超过 `v2_asr_meta_stale_max_hours` 小时视为陈旧并放弃）。
- 信号作用：run 状态 `suspect/empty/failed` → 显著警告 + 风险清单 warning + **闸门0 收紧**（仅收紧 default 删五类阈值，永不删除孤立应答词/无意义音节连缀）；语音覆盖率低于 `v2_asr_meta_min_coverage_pct` → 风险清单告警。
- 全部容错：无信号/解析失败/文件缺失时行为与 1.1 完全一致。信号内容以语义指纹参与 `--resume` 校验——规则、档位、阈值或信号变化都会使断点失效（保护产物正确性）。

### 7.4 隔离区

保险阀降级或关闭闸门0 时，高置信幻觉源文若仍被 LLM"翻译"出通顺中文，该条目会在终稿中移入 `{字幕名}_隔离区.srt`（主稿不再包含）；移出条数计入质量报告条数恒等式（"隔离区移出"项），运行摘要同步标注——请人工比对后决定取舍。

### 7.5 与 1.1 的行为差异及回退

- `default` 档下同一输入的成品条目数可能少于 1.1（纯标点行等在送翻前被删除）；运行摘要与质量报告【处置】章节均会给出计数。
- 需要完整复现 1.1 行为：`--source-filter off`。

### 7.6 三处规则/白名单的分工

| 位置 | 作用 |
|---|---|
| `config/rules/source_hallucination.yaml`（源侧） | 送翻前检测：类别参数、词表、keep_list 白名单 |
| 包内 `defaults/hallucination_patterns.yaml`（中文侧） | 翻译后兜底清洗：中文元信息词、垃圾正则 |
| `language_validator` 内置白名单（Python 集合） | 翻译后语言校验的防误杀保护（与源侧 keep_list 口径一致，有交叉守卫测试钉住） |

## 8. 运行日志

- 全量运行日志落盘：`Logs/M-D.txt`（同日多次运行追加时间后缀），自动保留 7 天；
- 失败/中断的运行日志归档到 `Logs/Errors/`（同一保留策略）；
- 流水线临时工作区：`Temp/`（`--clean-tmp-on-exit` 可在退出时清理 `.refine_tmp` 临时目录）。

## 9. FAQ

**FAQ-1：GBK 控制台中文/emoji 乱码或输出报错？**
程序内部已将标准流重配置为 UTF-8（errors=replace），尽量兼容中文 Windows 默认 GBK 代码页。若仍出现乱码，可在 CMD 先执行 `chcp 65001` 切换 UTF-8 代码页；NDJSON 模式下事件行使用纯 ASCII 转义，不受代码页影响。

**FAQ-2：提示 LM Studio 未启动/探测失败？**
先确认 LM Studio 已启动并加载了模型，且本地服务端口与端点一致（默认 `http://localhost:1234/v1`）。探测超时由 `timeout_probe`（默认 5 秒）控制；本地服务响应慢时可调大 `SUBTRANSJAV_TIMEOUT_PROBE`。

**FAQ-3：提示模型未指定？**
`lmstudio` / `ollama` / `siliconflow` / `custom` 服务商没有内置默认模型名，必须通过 `--s1-model` / `--s3-model`（或 GUI 对应下拉框）指定；`deepseek` / `zen` 有内置默认模型。GUI 用户在"阶段设置"中选择即可。

**FAQ-4：云端密钥怎么提供？三级解析顺序是什么？**
按顺序取第一个非空：① CLI/GUI 显式传入（如 `--deepseek-key`，注意命令行传密钥会暴露在进程列表，不建议）；② 环境变量（`DEEPSEEK_API_KEY` / `OPENCODE_API_KEY` / `SILICONFLOW_API_KEY` / `CUSTOM_API_KEY`）；③ GUI 保存的密钥（Windows DPAPI 加密存储于 `config/api_keys.bin`，绑定当前用户）。本地服务（LM Studio/Ollama）无需密钥。

**FAQ-5：--dry-run 是干什么的？**
`--dry-run` 只打印执行计划（输入文件、阶段配置、批处理预算等）并校验配置，不实际调用任何模型。配合退出码使用：`0` = 配置可用，`2` = 配置有误。批量任务前建议先跑一次。

**FAQ-6：GUI 启动报 WebView2 缺失？**
Windows 下 GUI 依赖 Microsoft Edge WebView2 运行时。下载安装"Evergreen Standalone Installer"后重试：https://developer.microsoft.com/en-us/microsoft-edge/webview2/

**FAQ-7：中断后想续跑，但提示指纹不匹配？**
说明输入字幕、配置、词库或 TM 库在中断后发生过变化。若确认变化无关紧要，可用 `--resume --force-resume` 强制复用旧阶段A 产物（注意错位风险）；否则去掉 `--force-resume` 直接重跑。

**FAQ-8：如何彻底重跑某个字幕？**
使用 `--force`（覆盖前自动备份旧产物）；若只想清掉断点状态从头再来，删除对应的 `{字幕名}_manifest.json` 后正常运行即可。

**FAQ-9：大量条目"阶段B 无译文"或整段保留日文原文？**
先确认依赖完整（本地 LM Studio 走 OpenAI 兼容协议，需要 Python 包 `openai` 与 `httpx`，缺失时批次会在 import 处静默失败并回退）；再确认模型在线、上下文窗口足够（`--v2-ctx`），必要时调小 `--batch-local` 或 `--v2-concurrency` 后用 `--resume` 重跑（只重做失败部分）。风险清单的 `critical` 条目会直接给出该提示。

## 10. 1.2.1 行为变化一览

相对 1.1，1.2.1 在"删除谁、保留谁、如何交待"上做了系统收敛，主要行为变化如下：

1. **删除权收归闸门0，下游不再删条**：阶段A/阶段B 与兜底规则层一律不物理删除条目；翻译失败的条目以 `[未翻译]` 前缀保留在终稿原文位置（不再静默消失），终稿条目数不再因模型故障无故减少。
2. **cleaner 源侧证据门槛**：兜底规则清洗引入源侧证据校验——原文有实义证据（汉字、足够长度等）的条目不再因中文侧规则被误删；`lenient` 档不运行规则清洗，与 `strict` 档的差异仅在于"证据存疑条目保留与否"。
3. **质量报告新增【处置】/【乱码强译复核】/【未翻译】小节与条数恒等式**：闸门0 删除台账、疑似乱码强译条目、`[未翻译]` 保留条目全部显式列出，并给出"原文 = 闸门0删除 + 预合并合并 + 规则清洗合并/删除 + 隔离区移出 + 终稿"的条数核对恒等式（失衡标 ⚠️）；随本变化，`{字幕名}_幻觉处置报告.json` 退场（见 7.2）。
4. **假名残留按条目归并**：质量报告的假名残留检查按条目归并展示，同一条目的多个假名片段不再重复展开为多条编号。

## 11. 1.2.2 行为变化一览

相对 1.2.1，1.2.2 聚焦"TM 治理、语境消歧、误译拦截与术语一致性"四条线，全部机制性变化如下（均不涉及任何具体词条译法）：

### 11.1 TM 治理与清洗工具 tm_purge

- **工具定位**：`tools/tm_purge.py` 以某个输入 srt 的源句为候选集，在 TM 库（`tm_entries`）中定位同源条目并生成清洗计划，用于清退错误/毒化条目。
- **dry-run 默认，零写入**：不带 `--yes` 时只产出审核用 CSV（utf-8-sig，Excel 直开不乱码），列含 `entry_id / source_text / target_text / match_type / action / reason / created_at / hit_count / suspect_cross_file`；实际删除必须显式 `--yes`，且执行前自动全量备份 `tm.db` 到带时间戳路径。
- **候选集三形态匹配**：`raw`（srt 原文逐条精确匹配）/ `premerge`（复现确定性预合并后形态精确匹配）/ `normalized`（NFKC+去标点+空白折叠后的等值匹配）；多形态同时命中按 raw > premerge > normalized 取 `match_type`，`reason` 列出全部命中形态。
- **白名单排除**：`--exclude-ids "1,2,3"` 与 `--exclude-file <txt>`（一行一个 entry_id，`#` 开头为注释）取并集；被排除条目在 CSV 中标 `would_keep_excluded`（reason：user_hold_whitelist）。典型流程：先 dry-run 出 CSV 人工审核，暂缓条目经排除参数承接，再决定是否 `--yes`。
- **探针**：`--probe "源句片段"` 快速验证单句是否命中库内条目（退出码 0=命中 / 1=未命中），不生成 CSV。
- **时间窗 `--since` / `--until`**（格式 `YYYY-MM-DD` 或 `YYYY-MM-DD HH:MM`，按 `created_at` 过滤）：`created_at` 为空的行归入 **unknown_time 组**——指定时间窗时默认**不删**（action=would_keep_unknown_time），除非显式 `--include-unknown-time`；未指定时间窗时 unknown_time 行正常进入删除候选（仍标 `suspect_cross_file=true`）。
- **删除清单 sha256 审计**：`--yes` 执行前对删除清单（entry_id 升序）计算 sha256，写入运行日志与 stdout，供事后核对删除范围是否被篡改。
- **两条风险定稿措辞（务必知悉）**：
  1. **清洗改变 TM 指纹，旧 resume 必然失效——删旧 resume 产物，禁止复用。**
  2. **旧 TM 无 provenance，清洗可能跨片误删同源句，只能靠 dry-run + CSV 备份兜底。**
- **跨片保守口径**：`source_name` 溯源列自 1.2.2 起新增（旧行为 NULL 不回填），仅来源与本片 srt 同名的行判定为本片产物；无法判定来源的行一律标 `suspect_cross_file=true` 并在摘要单列计数，供人工裁决。

### 11.2 per-片语境 sidecar（.context.md）

- **文件命名**：与待翻译 srt 同目录、同名、后缀 `.context.md`（如 `某影片.srt` 配 `某影片.context.md`）；不存在=无注入，零影响。
- **两个小节**：【剧情摘要】（2-5 行中性概述，供消解指代与歧义，不会改写原文）与【误听怀疑】（按片填写 ASR 疑似误听词条，格式 `疑似词 => 疑似正解`，仅当上下文无法按字面义解读时模型才按疑似义翻译）；标题必须原样保留，`#` 开头行为注释。模板见 `docs/上下文sidecar模板.md`。
- **开关**：`context_sidecar`（默认开启）；设为 `false`（如写进 `config/user_settings.json`）全局禁用。
- **注意**：sidecar 内容**不参与断点续跑指纹**——修改 sidecar 后请勿 `--resume` 复用旧阶段A 产物，需要生效请用 `--force` 重跑。

### 11.3 反义/拟声误译校验规则与档位差异

- 新增反义误译三规则（源文形态：やめて / 最低 / ずるい）与两条补充规则（身体语境「首」、イク 系假名变体高潮语境复核），规则全部在 `config/rules/translation_rules.yaml`（可整文件覆盖，与源侧白名单同惯例）。
- **双侧锚定**：源文命中指定形态 **且** 译文命中目标集才告警，单侧命中不触发，控制误报。
- **warn_only，不改稿**：告警只进质量报告"校验告警"复核清单，同时经 flagged_indexes 机制阻断该翻译对进入 TM 学习（幻觉/误译不入库扩散）；译文本身一律不动，由人工裁定。
- **档位差异（重要）**：本组规则**仅在 `v2_profile=local`（strict 兜底档）生效**；`cloud`（lenient 档）整层跳过规则清洗与误译拦截，不产生这些告警、也无对应 TM 拦截——这是两档的既定分工，不是缺陷。需要完整校验请用 local 档。

### 11.4 术语冲突观察闸与【术语一致性】章节

- **默认观察，不阻断**：译文与词库译法不一致时，1.2.2 先只做两件事——质量报告新增【术语一致性】（逐术语命中/别名/样本统计）与【术语冲突观察】章节（冲突样本逐条列出），并把冲突累计落盘观察记录（CSV/JSON），**不改稿、不拦截**。
- **转阻断由用户裁决**：观察一段时间确认口径后，显式开启 `glossary_conflict_block=True`——冲突条目禁止进入 TM 学习（入库前检查），是否进一步处理译文仍由人工决定。
- **别名不误报**：glossary 新增可选第三列 `target_aliases`（`|` 分隔多个候选译法），译文命中别名不算冲突；未填该列行为与旧版一致。

### 11.5 learned 自学习开关与重置工具

- **止增开关**：`glossary_learn_enabled=False` 时整段跳过 learned 词库自动学习（控制台显式提示），已入库内容不受影响。
- **存量清退**：`tools/glossary_learned_reset.py`——dry-run 默认零写入；`--yes` 实际执行且执行前先落带时间戳备份（`<原名>.bak-YYYYMMDD_HHMMSS`）；`--keep-term "词1,词2"` 白名单按源词保留指定词条其余清除。**只触碰 `glossary_learned.csv`，绝不写人工词库 glossary.csv。**

### 11.6 其他可见变化

- **质量报告 TM 摘要行**：新增"TM 命中/入库"摘要（H=阶段A 精确命中数、L=本次学习入库数；阶段A 复用或未启用 TM 时标"取不到"）。
- **`source_name` 溯源列**：TM 自学习入库统一记录来源 srt 文件名 stem（provenance 簿记列，不参与指纹）。
- **质量报告 CSV 编码**：改用 utf-8-sig，Excel 直开不乱码。
- **配置键入指纹**：`glossary_conflict_block` / `glossary_learn_enabled` / `context_sidecar` 等新治理开关纳入 `--resume` 指纹，变更后旧断点失效属预期保护行为。
- **纯假名实义行保护**：L7/L8/L11 规则收紧（源侧噪声证据门槛），实义纯假名行不再被兜底清洗误删，免删条目在质量报告显式计数（详见 10 节第 2 条机制的延伸收紧）。

### 11.7 剧情自摘要（Beta）

- **机制**：Beta 特性，`auto_synopsis` 默认开启。闸门0+预合并完成后、阶段A 前，把整片条目过滤纯噪声行后按起始时间排序分桶均匀采样（桶数 3-8 按总字符量自适应，`synopsis_max_chars` 默认 6000 字限幅），复用阶段A 服务商/模型做一次独立 LLM 调用（`max_tokens=300`、超时 min(timeout_llm, 300s)）生成 3-5 行中文剧情梗概（主要人物及关系 / 核心剧情线 / 场景构成），以【剧情背景（自动摘要·beta）】块注入 A/B 两阶段提示词，帮助模型消解指代与歧义；信息不足的维度模型会按约束写"信息不足"而非编造。
- **开关**：`--no-auto-synopsis` 关闭；也可写 `config/user_settings.json`（`"auto_synopsis": false`）或环境变量 `SUBTRANSJAV_AUTO_SYNOPSIS=false`。`synopsis_max_chars` 为抽样文本字符预算，可用 `config/user_settings.json` 调整。手写 sidecar【剧情摘要】小节非空时手写优先，自动摘要自动跳过并记日志。
- **缓存**：独立目录 `Temp/synopsis_cache/`（与翻译记忆库完全隔离，绝不写入 TM）。缓存键 = 提示词版本（PROMPT_VERSION）+ 服务商/模型 + 抽样文本的 sha1；命中不再调用 LLM，换 `--s1-model` 后键自然不同、自动重新生成。
- **边界（两条，务必知悉）**：
  1. **摘要内容与缓存不参与 `--resume` 指纹**（与 sidecar 内容同款已知边界）——换 `--s1-model` 或修改采样行为（`synopsis_max_chars` 等入指纹键除外）后，旧阶段产物可能复用旧提示词结果，需要让新摘要生效请用 `--force` 重跑。
  2. **摘要仅注入翻译提示词，不出现在任何产物**——终稿、质量报告、风险清单、TM、分歧 CSV 均不包含摘要文本；生成失败/空输出时记日志静默跳过，不影响管线继续翻译。
- **验收口径**：Beta 特性采用双轨验收——正式验收以关闭 beta（`--no-auto-synopsis`）的结果为准，另开 beta 做对比观察其对手写/审校质量的影响。
