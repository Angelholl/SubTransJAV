# SubTransJAV 使用与维护手册

面向中文用户的日文影片字幕双引擎翻译与精修工具链（v1.1）。本手册覆盖安装、配置、断点恢复、事件协议、翻译记忆库（TM）运维与常见问题，供日常使用与长期维护参考。

> 面向中文用户：默认翻译方向为 日文 → 中文。精修管线（refine）与角色卡模板当前未做英文等其他目标语言适配。

---

## 1. 安装

### 1.1 桌面 GUI（推荐普通用户）

使用仓库根目录的 `首次安装.bat`：

1. 双击运行，脚本自动在项目目录创建 `.venv` 虚拟环境；
2. 自动安装核心引擎与 GUI 依赖（`pip install -e ".[gui]"`）；
3. 默认源失败或超时时自动回退清华大学镜像源重试；
4. 完成后使用桌面"净语翻译"快捷方式启动（或命令行运行 `subtransjav-gui`）。

前置要求：Windows 10+，已安装 Python 3.10+ 并加入 PATH；运行 GUI 还需 Microsoft Edge WebView2 运行时（Win10/11 通常已内置，缺失时见 FAQ-6）。

### 1.2 命令行 CLI（推荐进阶用户）

要求 Python 3.10–3.13。

```bat
:: 核心翻译引擎 + CLI
pip install -e .

:: 含桌面 GUI
pip install -e ".[gui]"
```

入口命令：

- `subtransjav-refine`：精修翻译管线（阶段A 净语+翻译 → 阶段B 审校+抛光）；
- `subtransjav-gui`：桌面界面。

## 2. 配置分层与可调字段

### 2.1 优先级（从低到高）

```
内置默认值 < config/user_settings.json < SUBTRANSJAV_* 环境变量 < CLI/GUI 显式赋值
```

- `config/user_settings.json`：浅合并，仅下方表格中的字段生效；非法 JSON 或未知字段会被警告并忽略，不会中断运行；
- 环境变量命名规则：`SUBTRANSJAV_` + 大写字段名，如 `SUBTRANSJAV_TIMEOUT_LLM=600`；
- CLI/GUI 显式赋值优先级最高（构造后赋值天然生效）。

### 2.2 全部可调字段与默认值

| 字段名 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `temperature_cloud` | float | `0.5` | 云端服务商采样温度 |
| `temperature_local` | float | `0.1` | 本地服务商采样温度（实测最优低温） |
| `premerge_max_gap_s` | float | `8.0` | 断句预合并：合并后总时长上限（秒） |
| `premerge_max_items` | int | `3` | 断句预合并：合并条数上限 |
| `v2_concurrency_max` | int | `5` | 批间并发钳制上限 |
| `timeout_llm` | float | `900.0` | LLM 单批超时（秒；本地慢模型单批可达数分钟） |
| `timeout_http` | float | `60.0` | OpenAI 兼容 HTTP 客户端超时（秒） |
| `timeout_probe` | float | `5.0` | 本地服务探测类 GET 超时（秒） |
| `heartbeat_stale_s` | float | `45.0` | GUI 心跳超时阈值（秒；可经 `SUBTRANSJAV_HEARTBEAT_STALE_S` / `user_settings.json` 覆盖） |

`config/user_settings.json` 示例：

```json
{"temperature_cloud": 0.3, "timeout_llm": 600}
```

LLM 服务商与端点（`--s1-*` 阶段A / `--s3-*` 阶段B，均为"净语翻译 v2"两阶段语义）不在上表内，经 CLI 参数或 GUI 设置；本地服务 LM Studio / Ollama 有内置默认端点（`http://localhost:1234/v1`、`http://localhost:11434/v1`），不需要任何密钥。

## 3. 断点恢复（--resume / --force-resume）

### 3.1 工作机制

每次任务会持久化一份任务清单 `{字幕名}_manifest.json`，记录：

- 输入文件指纹（sha1、大小）、配置指纹、词库与 TM 指纹、各阶段模型信息；
- 各阶段状态机（`pending → running → done / degraded / failed`）与产物路径。

`--resume` 断点续跑：

1. 重算输入/配置/词库/TM 指纹并与清单比对；
2. 指纹全部匹配（清单可信）且阶段A 已完成、终稿未完成 → 复用上次中断任务的阶段A 产物（`{字幕名}_refine_A.srt`），直接进入阶段B；
3. 任一指纹不匹配 → 视为不可复用，整个任务从头重跑（清单按新指纹重建）。

`--force-resume`：配合 `--resume` 使用，指纹校验不匹配时仍强制复用旧产物（例如明知只改了无关配置、想省掉阶段A 费用时）。**注意：复用的阶段A 产物与当前输入可能不对应，需自行承担错位风险。**

### 3.2 与 --force 的区别

- `--resume`：复用**已完成的阶段A**，跳过重复计算；
- `--force`：忽略已有产物强制整任务重跑（覆盖前自动备份）。

### 3.3 manifest 自动清理

任务成功完成后，断点恢复相关产物（`{字幕名}_manifest.json` 与 `{字幕名}_refine_A.srt`）会被自动删除，不留垃圾文件；仅在任务中断/失败时保留，供下次 `--resume` 使用。

## 4. NDJSON 事件协议与退出码

### 4.1 开启方式

```bat
subtransjav-refine -i 字幕.srt ... --event-format ndjson
```

- 结构化事件以"每行一个 JSON 对象"输出到 stdout；人类可读文本全部转往 stderr；
- 心跳默认 20 秒一跳，可用 `--heartbeat-interval` 调整（GUI 依赖心跳判断进程存活）；
- 序列化使用 `ensure_ascii=True`，防止 Windows GBK 控制台破坏 JSON 行结构；
- 解析失败的行按普通日志处理（向前兼容）。

### 4.2 事件类型表（protocol_version = 1）

| 事件类型 | 含义 |
|---|---|
| `task_started` | 任务开始 |
| `phase_started` | 某阶段开始 |
| `phase_progress` | 阶段内进度推进 |
| `phase_finished` | 某阶段结束 |
| `warning` | 警告（不影响继续） |
| `degraded` | 静默降级显式化（该批/条目降级处理，如保留原文） |
| `error` | 错误 |
| `heartbeat` | 心跳（含 `last_phase` / `elapsed_s` / `interval_s`） |
| `task_finished` | 任务结束 |

事件行公共字段：`protocol_version`、`task_id`、`seq`（单调递增）、`timestamp`（秒级 ISO）、`type`、`phase`、`file`、`payload`（对象）。

### 4.3 CLI 退出码

| 退出码 | 含义 |
|---|---|
| `0` | 成功（含 dry-run 计划校验通过） |
| `1` | 执行异常失败 |
| `2` | dry-run 配置错误 / 参数问题 |
| `3` | 部分降级（存在降级/失败文件或风险事件，产物已生成但需人工复核） |
| `130` | 用户中断（Ctrl+C） |

> 注：`2` = 用法/参数错误（argparse 惯例，非法参数时由 `SystemExit(2)` 产生），与任务退出码 `0`/`1`/`3` 并存。

## 5. 翻译记忆库（TM）运维

### 5.1 存储位置

- 主库默认路径：`<项目根>/Temp/translation_memory/tm.db`（SQLite，句子级翻译记忆）；
- 可用 `--tm-db` 指定其他库文件（例如为测试单独建库）；
- 与词库（术语级，CSV）互补：TM 是句子级，词库是术语级。

### 5.2 匹配与学习

- 匹配策略：精确匹配（哈希查找，直接复用译文）→ 模糊匹配（字符重叠率 ≥ 阈值，默认 `--tm-threshold 0.85`，候选供提示）；
- 自学习带**准入门槛**：低质/可疑翻译不进词库（`--no-tm-learn-gate` 可关闭，仅用于 A/B 验证）；
- `--tm-stats` / `--tm-export` / `--tm-import` / `--tm-clear`：统计 / 导出 CSV / 从 CSV 导入 / 清空。

### 5.3 回灌口径

主库与测试库分离维护；批量回灌（把外部或历史译文并回主库）统一走 `--tm-export` 导出复核后经 `--tm-import` 人工执行，不做自动回灌。导入前建议先备份 `tm.db` 并用 `--tm-stats` 核对条目量。

## 6. 风险清单文件

- 有风险时自动生成 `{字幕名}_风险清单.md` 与 `.json`（无风险不生成）；
- 内容为管线运行中收集的风险事件，严重级别分 `info` / `warning` / `critical`；
- 用途：定位需人工复核的片段（如未翻译占比过高、语义可疑、触发加固规则的行）；
- 退出码 `3`（部分降级）通常伴随风险清单，建议优先复核 `critical` 条目。

---

## 7. 运行日志

- 全量运行日志落盘：`Logs/M-D.txt`（同日多次运行追加时间后缀），自动保留 7 天；
- 失败/中断的运行日志归档到 `Logs/Errors/`（同一保留策略）；
- 流水线临时工作区：`Temp/`（`--clean-tmp-on-exit` 可在退出时清理 `.refine_tmp` 临时目录）。

## 8. FAQ

**FAQ-1：GBK 控制台中文/emoji 乱码或输出报错？**
程序内部已将标准流重配置为 UTF-8（errors=replace），尽量兼容中文 Windows 默认 GBK 代码页。若仍出现乱码，可在 CMD 先执行 `chcp 65001` 切换 UTF-8 代码页；NDJSON 模式下事件行使用纯 ASCII 转义，不受代码页影响。

**FAQ-2：提示 LM Studio 未启动/探测失败？**
先确认 LM Studio 已启动并加载了模型，且本地服务端口与端点一致（默认 `http://localhost:1234/v1`）。探测超时由 `timeout_probe`（默认 5 秒）控制；本地服务响应慢时可调大 `SUBTRANSJAV_TIMEOUT_PROBE`。

**FAQ-3：提示模型未指定？**
`lmstudio` / `ollama` / `siliconflow` / `custom` 服务商没有内置默认模型名，必须通过 `--s1-model` / `--s3-model`（或 GUI 对应下拉框）指定；`deepseek` / `zen` 有内置默认模型。GUI 用户在"阶段设置"中选择即可。

**FAQ-4：云端密钥怎么提供？三级解析顺序是什么？**
按顺序取第一个非空：① CLI/GUI 显式传入（如 `--deepseek-key`，注意命令行传密钥会暴露在进程列表，不建议）；② 环境变量（`DEEPSEEK_API_KEY` / `OPENCODE_API_KEY` / `SILICONFLOW_API_KEY` / `CUSTOM_API_KEY`）；③ GUI 保存的密钥（Windows DPAPI 加密存储于 `config/api_keys.bin`，绑定当前用户）。本地服务（LM Studio/Ollama）无需密钥。

**FAQ-5：--dry-run 是干什么的？**
`--dry-run` 只打印执行计划（输入文件、阶段配置、批处理预算等）并校验配置，不实际调用任何模型。配合退出码使用：`0` = 配置可用，`2` = 配置有误。批量任务前建议先跑一次。

**FAQ-6：GUI 启动报 WebView2 缺失？**
Windows 下 GUI 依赖 Microsoft Edge WebView2 运行时。下载安装"Evergreen Standalone Installer"后重试：https://developer.microsoft.com/en-us/microsoft-edge/webview2/

**FAQ-7：中断后想续跑，但提示指纹不匹配？**
说明输入字幕、配置、词库或 TM 库在中断后发生过变化。若确认变化无关紧要，可用 `--resume --force-resume` 强制复用旧阶段A 产物（注意错位风险）；否则去掉 `--force-resume` 直接重跑。

**FAQ-8：如何彻底重跑某个字幕？**
使用 `--force`（覆盖前自动备份旧产物）；若只想清掉断点状态从头再来，删除对应的 `{字幕名}_manifest.json` 后正常运行即可。
